Put your pages online.

Pixie maps simple URL names to HTML files in a single directory.

Create a site directory

mkdir -p my-site
printf '<!doctype html><title>My site</title><h1>Hello</h1>' > my-site/hello.html
printf '<!doctype html><title>About</title><h1>About us</h1>' > my-site/about.html
printf '<!doctype html><title>Not found</title><h1>Page not found</h1>' > my-site/404.html
RequestFile
/hello.html
/aboutabout.html
/about?lang=enabout.html
/missing404.html, with status 404
Use HTML page routes.

Names may contain ASCII letters, digits, hyphens, and underscores. Nested paths, encoded characters, direct .html URLs, CSS, JavaScript, images, directory indexes, and SPA fallback are not supported by the current router. Inline CSS and JavaScript in your HTML when needed. Keep symlinks out of an untrusted web root.

Mount a site into Docker

From the directory containing my-site/:

docker run --rm -p 8080:8080 \
  -v "$PWD/my-site:/usr/share/pixie/web:ro" \
  -e PIXIE_WEB_ROOT=/usr/share/pixie/web \
  ghcr.io/laflut3/pixie:latest

For a local source build, set PIXIE_WEB_ROOT to the same directory instead. Each request reads the current file; restarting is unnecessary for page edits.

Use your Linux service

The packaged service uses /usr/share/pixie/web. To use a custom root, add a systemd override:

sudo systemctl edit pixie
[Service]
Environment=PIXIE_WEB_ROOT=/srv/pixie/site
sudo systemctl daemon-reload
sudo systemctl restart pixie

Create the directory first and ensure the service account can read the files and traverse the parent directories. The supplied unit protects home directories, so use a path such as /srv/pixie/site.

Need more than one site?

Use separate Pixie instances behind a reverse proxy to select a site by domain name.
