User guide

Host multiple sites

Run one Pixie instance per site behind NGINX.

One instance per site

Pixie does not select a site by host name. Each process has one web root and listener. Run each site on a local port, then route domains through NGINX.

Browser → NGINX :80 → Pixie :8081 / :8082

Start two instances

Create /srv/pixie/alpha and /srv/pixie/beta, each with hello.html and 404.html. Save these configs:

# /etc/pixie/alpha.yml
addr: 127.0.0.1:8081
workers: 4

# /etc/pixie/beta.yml
addr: 127.0.0.1:8082
workers: 4

Run them in separate terminals. Use a service manager in production.

PIXIE_CONFIG=/etc/pixie/alpha.yml PIXIE_WEB_ROOT=/srv/pixie/alpha pixie
# In another terminal:
PIXIE_CONFIG=/etc/pixie/beta.yml PIXIE_WEB_ROOT=/srv/pixie/beta pixie

Route domains with NGINX

Add these blocks to NGINX. Replace the example domains and point DNS to this host.

server {
    listen 80;
    server_name alpha.example.com;
    location / {
        proxy_pass http://127.0.0.1:8081;
        proxy_set_header Host $host;
    }
}

server {
    listen 80;
    server_name beta.example.com;
    location / {
        proxy_pass http://127.0.0.1:8082;
        proxy_set_header Host $host;
    }
}

sudo nginx -t
sudo systemctl reload nginx
curl -H "Host: alpha.example.com" http://127.0.0.1/

For HTTPS, configure TLS on NGINX or on each Pixie instance. See TLS and mTLS.

Serve sites under path prefixes

NGINX can strip a path prefix before proxying:

location /alpha/ {
    proxy_pass http://127.0.0.1:8081/;
    proxy_set_header Host $host;
}
location /beta/ {
    proxy_pass http://127.0.0.1:8082/;
    proxy_set_header Host $host;
}

The trailing slash strips the prefix: /alpha/about reaches Pixie as /about. Use relative links. Pixie does not serve assets.
