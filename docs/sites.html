User guide

Host multiple sites

Choose a site by hostname. Pixie checks the site folders on every request.

Create site folders

sudo mkdir -p /etc/pixie/sites/{default,alpha.example.com,beta.example.com}
sudo cp -R ./site-a/. /etc/pixie/sites/alpha.example.com/
sudo cp -R ./site-b/. /etc/pixie/sites/beta.example.com/

Pixie serves the matching hostname folder and falls back to default/. Each site can contain HTML, CSS, JavaScript, images, and other static files. Put index.html at the site root.

curl -H 'Host: alpha.example.com' http://localhost:8080/

Mount a React build

docker run --rm -p 8080:8080 \
  -v "$PWD/dist:/etc/pixie/sites/default:ro" \
  -e PIXIE_SPA_FALLBACK=true \
  ghcr.io/laflut3/pixie:latest

Build the app first so dist/ exists. The fallback serves index.html for extensionless client-side routes.

Bake a site into an image

FROM ghcr.io/laflut3/pixie:latest
COPY dist/ /etc/pixie/sites/default/

Change the sites directory

PIXIE_SITES_ROOT=/srv/pixie/sites

Single-site deployments can keep using PIXIE_WEB_ROOT. A reverse proxy such as NGINX can terminate TLS or forward requests; preserve the original Host header for hostname routing.
