How it works

Request flow

From startup to response.

The request path

  1. Configuration

    main.rs loads config and resolves the address, workers, and TLS files.

  2. Connection acceptance

    server.rs accepts TCP connections and starts a Hyper task for each one.

  3. TLS handshake

    When enabled, rustls checks the server credentials and, with mTLS, the client certificate.

  4. HTTP parsing

    Hyper parses HTTP/1.x or HTTP/2. Pixie accepts GET and HEAD, then passes the path to the router.

  5. Route and file

    The router maps a page name to an HTML file in the web root.

  6. Response

    Hyper sends the status, headers, and body. HTTP/1 closes after one response. HEAD omits the body.
