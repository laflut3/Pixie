TLS and mTLS

Enable HTTPS or require client certificates.

Enable HTTPS

Save this config. Make both PEM files readable by Pixie:

addr: 0.0.0.0:8443
workers: 4
tls:
  cert_file: /etc/pixie/tls/server-chain.pem
  key_file: /etc/pixie/tls/server-key.pem

Put the server certificate first in the chain, followed by intermediates. Use an unencrypted PEM key valid for the client hostname. Restart Pixie after renewal.

curl --cacert server-ca.pem https://localhost:8443/

Omit --cacert for a system-trusted certificate. Pixie does not issue or renew certificates. This listener serves HTTPS only and does not redirect HTTP.

Require client certificates

Add the trusted client CA bundle:

tls:
  cert_file: /etc/pixie/tls/server-chain.pem
  key_file: /etc/pixie/tls/server-key.pem
  client_ca_file: /etc/pixie/tls/client-ca.pem

curl --cacert server-ca.pem \
  --cert client.pem --key client-key.pem \
  https://localhost:8443/

Pixie rejects clients without a valid certificate from that CA. It does not provide user accounts or route-level authorization.

Container and Kubernetes setup

Mount the config and certificates as read-only files, then expose the TCP port. Deployment templates do not mount credentials.

docker run --rm -p 8443:8443 \
  -v "$PWD/config-pixie.yml:/etc/pixie/config-pixie.yml:ro" \
  -v "$PWD/tls:/etc/pixie/tls:ro" \
  ghcr.io/laflut3/pixie:latest

Allow the pixie user to read the files. In Kubernetes, mount a Secret. TLS terminated at an Ingress leaves the Ingress-to-Pixie connection unencrypted unless you configure TLS there too.

Experimental HTTP/3

HTTP/3 is experimental and uses QUIC over UDP. Set http3.addr; in Helm also set tls.enabled=true, tls.secretName, and http3.enabled=true. Expose the UDP port. The chart mounts the Secret at /etc/pixie/tls.

When a connection fails

  • Startup error: check config syntax, certificate chain, key, paths, and permissions.
  • Trust error: check the hostname and server CA.
  • mTLS error: check the client certificate, key, expiry, and CA.
  • Connection refused: check the port, service, and firewall.
