Small Rust HTTP server
User guide

One file. A few options.

Set the listener, concurrency, and TLS credentials with YAML. Select your pages through an environment variable.

A plain HTTP configuration

addr: 0.0.0.0:8080
workers: 4
PIXIE_CONFIG=./config-pixie.yml PIXIE_WEB_ROOT=./my-site cargo run --locked

Save the YAML as config-pixie.yml. Paths in configuration are resolved from the process working directory, so use absolute paths for services.

Configuration reference

SettingDefaultMeaning
addr127.0.0.1:80Full listen address. Takes priority over host and port.
host127.0.0.1Used with port when addr is absent.
port80TCP listen port.
workers4Connection worker count. Zero falls back to 4.
tls.cert_fileAbsentRequired PEM certificate chain when tls is present.
tls.key_fileAbsentRequired unencrypted PEM private key.
tls.client_ca_fileAbsentTrusted client CAs; setting it requires client certificates.

address is an alias for addr; nb_worker is an alias for workers. Port 80 may require elevated privileges; prefer 8080 for local use. The shipped sample configuration uses 8080.

Which file is loaded?

  1. If PIXIE_CONFIG is nonempty, Pixie uses that path.
  2. Otherwise, it looks for config-pixie.yml in the working directory.
  3. Then it looks for /etc/pixie/config-pixie.yml.
  4. Without a file, compiled defaults apply.
A missing explicit file falls back to defaults.

When PIXIE_CONFIG points to a missing file, the other file locations are skipped. Invalid YAML fails startup. Check the startup log for the actual address.

Web root lookup

  1. An existing directory selected by PIXIE_WEB_ROOT.
  2. web/ at the source manifest path, if present.
  3. /usr/share/pixie/web.

An invalid PIXIE_WEB_ROOT produces a warning and uses the fallback. Set it explicitly for custom sites. Restart Pixie after changing config or TLS files; page files are read on each request.
